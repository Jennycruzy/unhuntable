# AI agents

A second door into the same pieces, paid per call with x402. The MCP server and its setup are in [`agent/`](../agent/).

Agents get hunted more than people: their wallets are public, they trade on schedules, and a prompt injection can talk them into giving away their stop. Unhuntable gives an agent the same protection as a person, through an MCP server (`agent/`) and a paid HTTPS API.

- **The owner sets the limits.** On the Agents screen the owner makes a key for each agent: the largest size it may open, which markets, and how many opens a day. The key is shown once and stored only as a hash. Each call the agent makes is listed with its payment.
- **The stop is sealed on the agent's machine.** `unhuntable_set_stop` seals the price into one box per piece that only the guard's enclave can open. It never reaches Hyperliquid's book and no tool can read it back, so there is nothing for a hunter, or a hostile prompt, to get out of the agent.
- **The agent cannot move money.** It opens and closes on pieces the owner already set up. Making pieces, moving money and trading stocks all need the owner's 12 words, which never leave the owner's browser.
- **Every call is paid with x402 in USDC on NEAR.** The first request gets a `402` with an x402 v2 challenge; the agent signs a NEP-366 delegated `ft_transfer` of the price (0.002 USDC by default) to `unhuntable.near`, and the server settles it on NEAR before the call runs, with its own relayer paying the gas. Limits are checked before payment, so a refused call costs nothing. Built on FastNEAR's `@fastnear/x402` and the x402 Foundation's NEAR scheme.

- **Agents can follow traders.** `unhuntable_traders` lists traders, their prices and their guard-signed records for free; `unhuntable_trader_trades` reads the closed trades of a trader the owner holds a key to; `unhuntable_follow` asks the owner for a copy key (within the agent's largest size) or a viewing key, which waits for the owner's approval in the app, because only the owner's wallet can let the private balance pay a trader. [Followers](followers.md)

**Live on mainnet:** our own demo agent ran the real MCP server against tryunhuntable.site and paid for each call with x402. [The first payment](https://nearblocks.io/txns/7VcZWHJzgrauZaY6irWh1BiHGcr7kDch92UG69MFvMBD) moved 0.002 USDC from the agent's NEAR account to `unhuntable.near`, submitted and paid for by our relayer; [the next](https://nearblocks.io/txns/6XQ9FdGdfuhGYJcinGyHedhqoBCvxorQ1figfR2RAdaL) took 4.5 seconds from the tool call to the answer. Two opens outside the key's limits were refused in under 0.2 seconds and cost the agent nothing.

**Or pay from any chain, through PingPay.** The same `402` challenge also lists PingPay Agent Pay's offers for the main ways to pay: USDC on NEAR, Base, Ethereum, Arbitrum and Solana, NEAR, and Bitcoin (Ping takes about 200 tokens on 30+ chains; `PINGPAY_ASSETS` picks which go in the challenge, which must stay small enough for one HTTP header). The agent picks one and sends a `quote` payload with its own refund address; Ping answers through the server with a one-time NEAR Intents deposit address and the exact amount, for example 0.202021 USDC from NEAR for a 0.2 USDC call. The agent deposits on its own chain and sends the deposit proof; Ping settles 0.2 USDC to `unhuntable.near` through 1Click, and only then does the call run. A settled deposit pays for one call only: the server claims it with Ping before running anything. Settling goes through 1Click and can take minutes; until it is done the call answers `payment_settling`, and the agent sends the same proof again. Our MCP server pays this way with `UNHUNTABLE_PAY_WITH=pingpay`, depositing from its NEAR account with an ordinary `ft_transfer` (it registers the deposit address with the token first when needed). It saves each deposit's proof before sending it, so a client timeout or a restart never loses a paid deposit: the next call for the same request sends the saved proof instead of paying again. The plain USDC transfer stays first in the challenge, so existing x402 clients keep paying 0.002 USDC as before.

Switch it on with `X402=on` (the server's relayer settles payments), and add `pingKey` (a PingPay Agent Pay API key, with `unhuntable.near` as the recipient) to the secrets file for the PingPay way and connect any MCP client with the settings the Agents screen shows. Tests: `server/test/agents.test.ts` (keys, limits, refusals before payment, open → seal → status → close with each call paid and recorded), `server/test/x402.test.ts` (the real x402 library's challenge: 2000 units of Circle's USDC on NEAR to our account), `server/test/pingpay.test.ts` (both ways in one challenge, quote, deposit, settling, one call per deposit, Ping down), `agent/test/pingpay.test.ts` (the agent's quote, deposit and retries), and `agent/test/agent.test.ts` (a full MCP session in which no tool answer and no request ever carries the stop price).
